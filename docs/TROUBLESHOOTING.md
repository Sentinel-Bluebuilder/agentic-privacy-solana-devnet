# Troubleshooting: symptom → cause → command

For `devnet-dvpn` v0.3.0-rc8, macOS Apple silicon included ([`AGENTS.md`](../AGENTS.md); older releases: [`OLDER-RELEASES.md`](OLDER-RELEASES.md)). Every `code` here is a real one; its full row
(meaning, whether money moved, next, the other way out) is in [`CODES.md`](CODES.md), linked from the Code column. Terms:
[`GLOSSARY.md`](../GLOSSARY.md).

First, always:

```sh
devnet-dvpn agent status --json      # read "next" (and "alsoNext"); run it as printed
```

A failure line `{"ok":false,…}` carries `action` (rc7: `next`, the same line): run it. `money` says whether money moved; `docUrl` links the code's row. Use this page when
`action` is null, or when the symptom has no code. Path B (`direct/*.sh`) codes link to `CODES.md#code-direct-<code>`.

## Every onboarding state

In order. `agent status --json` names the one you are in, and its `next` is the line to run. "Section" = a section of [`AGENTS.md`](../AGENTS.md).

| State | How you see it | Run |
|---|---|---|
| Not installed | `devnet-dvpn: command not found` | section 1 (the install line for your OS) |
| No admin / root | the installer or `daemon install` refuses (on Windows rc.8 a standard user is told `no-wallet`, then `device-not-ready`, before any elevation refusal: do not run `device setup --yes` to get past it, it costs about 0.05 SOL and `daemon install` still needs an elevated shell) | ask a person for an elevated shell; section "Before you start" |
| No wallet | `code` `no-wallet`, or status without `address` | `devnet-dvpn wallet create --keyfile <path> --yes`, or load the key file you had |
| Key file missing / readable by others | `keyfile-missing` / `keyfile-mode` (exit 4; the mode is checked on Linux and macOS) | point `DVPN_KEYFILE` at the file / `chmod 600 <file>` |
| Not funded | `not-funded` (exit 4), or status `next` = `send at least …` | section 3: the operator sends the SOL (0.06 before setup) and tDVPN to `address` |
| Device not set up | `no-device-key`, or status `next` names `device setup` | `devnet-dvpn device setup --yes` |
| Service not installed / stopped | `daemon-missing`, `service: false` | `devnet-dvpn daemon install --yes` (root / admin) |
| Clock wrong | `clock-skew` (exit 4) | the time-sync line in its `next`, then `agent up --yes` |
| Deposit above the limit / the cap | `spending-limit` / `price-cap` (exit 4, nothing paid) | its `action` (your line pinned to the node), or your own `--max-price` |
| No node matches | `no-nodes` | its `action` (names the blocker: price, country, protocol or your `--node`) |
| Internet blocked | `blocked: true`, `kill-switch-held` | `devnet-dvpn daemon restore-network`, then `agent up --yes` |
| Connected | `connected: true` | `devnet-dvpn agent down --yes` when done |
| Deposit open, no session | `deposits` with `open` | `devnet-dvpn agent down --yes` first, never `agent up` |
| Deposits closing | `deposits` with `closing`, `readyAt` | `devnet-dvpn settle run --yes` after that time, then `devnet-dvpn settle withdraw --yes` |

## By symptom


| Symptom | Code | Cause | Command |
|---|---|---|---|
| `agent up` connected but `exitIp` is `null` | none | The address check did not finish within 8 s. The tunnel may be fine. | `devnet-dvpn quality ip --json`: `direct.ip` (whole-device protocols) or `viaSocks.ip` (V2Ray / Xray on Linux) must differ from your own address. |
| `exitIp` (or `quality ip`) shows your **own** address while `connected` is true | [`server-stopped`](CODES.md#code-server-stopped) | The node stopped serving; for a few seconds `agent status` can still say `connected`. Then it answers `"code":"server-stopped"`. The deposit is safe. | `devnet-dvpn agent up --yes` (another node; the dead one is skipped 10 min), or `devnet-dvpn agent down --yes` (closes the deposit). With `"blocked": true` as well: `devnet-dvpn daemon restore-network` first (`next`), then one of those two (`alsoNext`). |
| `quality ip` shows **no** address after `agent down`, or `agent status` says `"blocked": true` | none | The kill switch still holds the block (the session had dropped before you disconnected). | `devnet-dvpn daemon restore-network` (now), then `devnet-dvpn daemon set --kill-switch off --yes` (so it does not come back). Or `devnet-dvpn agent up --yes` to reconnect with protection. rc7: with no session, `next` is that `agent up --yes` and `alsoNext` is `daemon restore-network`. |
| macOS (rc8), kill switch on, the VPN service was killed: `devnet-dvpn daemon restore-network` answers `daemon-unavailable` ("Restart the Mac") with no `next`, and there is no internet | [`daemon-unavailable`](CODES.md#code-daemon-unavailable) | `restore-network` cannot lift the block while the service is down (an rc8 bug, being fixed for rc9). | `sudo launchctl kickstart -k system/co.sentinel.sentinel-dvpnd.c0`, then `devnet-dvpn daemon restore-network`; if still blocked, `sudo pfctl -a sentinel-dvpn-c0 -F all` (this app's rules only; never without `-a`, never `pfctl -d`). |
| `agent status` says `"reconnecting": true` (rc7) | none | The live session dropped and is reconnecting; the kill switch blocks the internet meanwhile (`connected` false, `blocked` true). The deposit stays open. | Wait a minute and run `agent status --json` again, or run `next` (`devnet-dvpn daemon restore-network`) to go direct now; `alsoNext` names reconnect / close. |
| `agent status` `next` is `devnet-dvpn agent up` with no `--yes` (rc7) | none | The device has no spending permission left, or the wallet holds under 1 tDVPN (with `held`). | Run it as printed: the preview pays nothing and names what is missing (funding or a limit), then follow its `next`. |
| `agent up` refused while the kill switch blocks | [`kill-switch-held`](CODES.md#code-kill-switch-held) | The block lets through only the last node, so this connect cannot lift it. Nothing was paid. | `devnet-dvpn daemon restore-network, then devnet-dvpn agent up --yes` |
| SSH session lost after a connect or after turning the kill switch on | none | The kill switch blocks everything that is not the tunnel; over a LAN, `--allow-lan` was off. | From a second way in (cloud console, serial console, a person at the machine): `devnet-dvpn daemon restore-network`, then `devnet-dvpn daemon set --kill-switch off --yes`. Before next time: `devnet-dvpn daemon set --allow-lan true --yes` (LAN), and never the kill switch over internet SSH without another way in ([`agent-safety.md`](agent-safety.md)). |
| `agent up` refused, exit `4`: the limit is below the deposit | [`spending-limit`](CODES.md#code-spending-limit) | This computer's spending limit is below this deposit, and `--raise-limit` was not given. Nothing was paid. | Run the `action`: your line pinned to the node it picked, with `--raise-limit --yes` (your `--protocol` and `--max-price` kept). Or set your own limit: `devnet-dvpn device setup --allowance N --yes` (N in tDVPN, above the deposit). Or a smaller deposit: fewer `--units`. |
| `agent up` refused, exit `4`: the deposit is above the default cap | [`price-cap`](CODES.md#code-price-cap) | No `--max-price` was given and the deposit is above the default cap (`defaults.priceCap`: the larger of the spending limit / 10 and the market p75 price × units). Nothing was paid. | Run the `action` (it names the node's price with `--max-price`), or ask for less: fewer `--units`, or `--max-price 0.01` for a cheaper node. |
| `agent up` answered `limitRaised` / `limitNote` and you did not want it | none | You ran it with `--raise-limit`, so it raised the limit for this deposit. A cap, not a charge. | Lower it: the command in `limitNote` (`devnet-dvpn device setup --allowance <N> --yes`). |
| `agent up` refused: not enough SOL or tDVPN for the step | [`not-funded`](CODES.md#code-not-funded) | Less SOL than the step needs (about 0.06 before this computer is set up, fees only after) or less tDVPN than the deposit; `error` names the exact shortfall and a recommended amount that also covers a reconnect. Nothing was paid. | Fund the address in `action`, then `devnet-dvpn agent up --yes`. Or `devnet-dvpn agent up --units <fewer> --yes`. |
| `agent up` refused: the picked node costs more than you hold | [`not-enough-tdvpn`](CODES.md#code-not-enough-tdvpn) | The node `agent up` picked costs more than you hold. Nothing was paid. | `devnet-dvpn agent up --max-price 0.01 --basis per_gb --yes`, or fund more tDVPN. |
| Funding: the operator sees a faucet limit message | none | Each faucet allows **2 requests every 8 hours**, shared by everyone on the network; the Sentinel faucet also has a daily total. | tDVPN: anyone holding some runs `devnet-dvpn wallet send --to <ADDRESS> --tdvpn 100 --yes`, or wait the time the faucet names. SOL: `solana airdrop 1 <ADDRESS> --url devnet`, or wait; about 0.06 SOL is enough. Done when `agent status --json` shows `sol` above 0.06 and `tdvpn` at least the deposit ([`AGENTS.md`](../AGENTS.md) section 3). |
| A deposit stays in `deposits` with `status` `closing` | none | A per-GB deposit takes about 2 hours to close (stage 1 of 2). Normal. | After `readyAt` (Unix seconds): `devnet-dvpn settle run --yes`, then `devnet-dvpn settle withdraw --yes`. `next` of `agent status` names the time. |
| A deposit stays `open` with no session | none | It was never closed (a failed connect after paying, `node-refused`, or a dropped session). | `devnet-dvpn agent down --yes`. Never `agent up` first: it would open a second deposit. |
| `agent down` answers `notClosed` / `warning` | none | The deposit was opened by another device of this wallet (a replaced computer); this computer cannot close it. | `devnet-dvpn device revoke --device <device> --yes` (if not revoked yet), then `devnet-dvpn settle run --device <device> --yes` |
| `agent down`: the disconnect is done but the refund run did not finish | [`busy`](CODES.md#code-busy), [`settle-failed`](CODES.md#code-settle-failed), [`daemon-gone`](CODES.md#code-daemon-gone) | The refund run did not finish. Nothing was lost. | `devnet-dvpn settle list`, then `devnet-dvpn settle run --yes` |
| `settle withdraw` failed | [`withdraw-failed`](CODES.md#code-withdraw-failed) | The withdraw transaction failed; the balance (`held`) is still there. | `devnet-dvpn settle withdraw --yes` again. "Nothing to withdraw" (exit 0) is not a failure. |
| `agent status` says `"service": false` on a computer where the service **was installed** (it was stopped, e.g. `systemctl stop`, or did not start after a reboot) | none in status; then [`daemon-unavailable`](CODES.md#code-daemon-unavailable) / [`service-down`](CODES.md#code-service-down) | The service unit (Linux: `sentinel-dvpnd@c0.socket` + `sentinel-dvpnd@c0`) is installed but not running. The wallet, the device and the deposits are fine; this is not a reinstall. | rc7: `devnet-dvpn daemon install --yes` (its `next` says so; on an installed service it starts it again, the wallet and device stay). rc.8 on Linux: `next` names the start itself (W47), and `daemon doctor` has a service row that says whether the unit is active. Linux by hand: `sudo systemctl start sentinel-dvpnd@c0.socket sentinel-dvpnd@c0`. Then `devnet-dvpn daemon doctor --json`. macOS (rc8, proven): `next` is `sudo launchctl bootstrap system /Library/LaunchDaemons/co.sentinel.sentinel-dvpnd.c0.plist`; run it, then `devnet-dvpn agent up --yes`. |
| The VPN service is not running or not answering | [`daemon-unavailable`](CODES.md#code-daemon-unavailable), [`service-down`](CODES.md#code-service-down) | The VPN service is not running or not answering. | `devnet-dvpn daemon doctor --json` (no check may say `"level": "fail"`); if it is not installed: `devnet-dvpn daemon install --yes` (administrator / root). |
| The service is starting or stopping | [`service-not-ready`](CODES.md#code-service-not-ready) | The service is starting or stopping. | The same command again in a moment. |
| The VPN service is not installed | [`daemon-missing`](CODES.md#code-daemon-missing) | Nothing was paid. | Linux / macOS: `devnet-dvpn daemon install --yes` as root or with passwordless `sudo`. Windows: see the next row. |
| Windows: a UAC prompt appears and nothing happens | [`daemon-relogin`](CODES.md#code-daemon-relogin) | The shell is not elevated (an agent cannot answer UAC), or the service pipe does not accept this account yet. | Run `devnet-dvpn daemon install --yes` once from an **elevated** PowerShell or an administrator SSH login. After `"relogin": true`, a non-elevated shell needs a new sign-in or SSH session. |
| macOS over SSH: "The login Keychain is locked in this session" | none | Without a key file the wallet is kept in the login Keychain, which stays locked in an SSH session. | Use a key file: `export DVPN_KEYFILE="$PWD/agent-key.json"` (or `--keyfile <path>`); a key-file wallet never touches the Keychain. Or unlock it: `security unlock-keychain` (needs the password). |
| The key file is gone, exit `4` | [`keyfile-missing`](CODES.md#code-keyfile-missing) | The file `DVPN_KEYFILE` / `--keyfile` names is gone. The funds stay with that key. | Restore the file from your backup and run the command again. Never `wallet create`: a new wallet holds none of the funds. |
| "No wallet" but you had one | [`no-wallet`](CODES.md#code-no-wallet) | `DVPN_KEYFILE` is not set in this shell (it lives only in the shell that set it). | `export DVPN_KEYFILE=<full path>` (PowerShell: `$env:DVPN_KEYFILE = '<full path>'`), or `devnet-dvpn wallet import <file>`. Never `wallet create`. |
| This computer is set up for another wallet | [`wallet-switch-needed`](CODES.md#code-wallet-switch-needed) | Nothing was paid. | Load that wallet's key file, or `devnet-dvpn device switch --yes`. |
| The clock is off | [`clock-skew`](CODES.md#code-clock-skew) | This computer's clock is off (the error says by how much). Nothing was paid. | Run the time-sync line in `next` (Windows: `w32tm /resync` in an elevated shell), then `devnet-dvpn agent up --yes`. macOS: if `sntp` says `Exchange failed: Timeout`, this network blocks time sync (NTP, UDP 123): set the date and time by hand (System Settings > General > Date & Time, automatic off), then `devnet-dvpn daemon doctor --json` again. |
| The node refused after the deposit opened | [`node-refused`](CODES.md#code-node-refused) | It is skipped next time. | `devnet-dvpn agent down --yes` (closes that deposit), not `agent up`. |
| `agent up` failed with no known cause (rc6, rc7) | [`unknown`](CODES.md#code-unknown) | The connect failed with no known cause. It is not known whether a deposit was opened (money `unclear`). | `devnet-dvpn agent status --json` first (it lists any deposit), then `devnet-dvpn logs --lines 80`, then `devnet-dvpn agent up --yes` once more. |
| The connect failed with no code | [`connect-failed`](CODES.md#code-connect-failed) | It is not known whether a deposit was opened. | `devnet-dvpn agent status --json`: a deposit in `deposits` with no session → `devnet-dvpn agent down --yes`; none → read `error`, then `agent up --yes` once more. |
| No online node matches | [`no-nodes`](CODES.md#code-no-nodes) | No online node matches the filters. No transaction ran. | `devnet-dvpn nodes list --online --json`, then widen `--protocol` / `--country` / `--max-price` (and check `--basis`). Under `--max-price`, `error` names the cheapest matching price and `action` is a runnable line with it: run it if you accept that price. |
| The device key could not be made | [`no-device`](CODES.md#code-no-device) | Nothing was paid. | `devnet-dvpn daemon doctor --json`; fix the check that says `"level": "fail"`. |
| `--plan` given, but no subscription | [`no-subscription`](CODES.md#code-no-subscription) | The wallet has no subscription to that plan. Nothing was paid. | `devnet-dvpn plans list`, then `devnet-dvpn plans subscribe <plan> --yes`, or drop `--plan`. |
| The key file is readable by other users, exit `4` | [`keyfile-mode`](CODES.md#code-keyfile-mode) | The key file can be read by other users of this computer. Nothing was paid. | `chmod 600 <the key file named in error>`, then `devnet-dvpn agent up --yes` (Linux, macOS; on Windows rc.8 does not check the file's ACL). |
| Path B: `install.sh` refuses the key file given as `KEYFILE=`, exit `5` | [`key-unsafe`](CODES.md#code-direct-key-unsafe) | The file's mode is not 600 or 400, so other users can read the secret key. Nothing was copied. | `chmod 600 <file> && sudo KEYFILE=<file> sh direct/install.sh` |
| The Solana connection (RPC) does not answer | [`rpc-unavailable`](CODES.md#code-rpc-unavailable), [`rpc-ws`](CODES.md#code-rpc-ws), [`rpc-network`](CODES.md#code-rpc-network), [`rpc-quota`](CODES.md#code-rpc-quota) | The Solana connection (RPC) the VPN service uses does not answer. `money` says whether a deposit may be open. | Run `next`: `devnet-dvpn daemon set --rpc <https url> --yes` (any Solana devnet RPC, e.g. `https://api.devnet.solana.com`), then `devnet-dvpn agent up --yes`. With money not `none`: `devnet-dvpn agent status --json` first. |
| Anything else | any | | `devnet-dvpn daemon doctor --json`, `devnet-dvpn logs --lines 80`, and the row for the `code` in [`CODES.md`](CODES.md). |
